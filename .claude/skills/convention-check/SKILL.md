# 컨벤션 검사

변경된 코드가 이 프로젝트의 컨벤션을 지키는지 검사합니다.

## 절차
1. 현재 브랜치에서 변경된 코드를 가져온 후 
2. 같은 폴더의 `convention.md`를 읽어 규칙을 확인한다.
3. 검사 대상을 정한다. 인자로 파일이나 경로가 주어지면 그것을, 없으면 `git diff HEAD`로 변경된 파일(`src/` 아래의 `.ts`, `.tsx`)을 대상으로 한다.
4. 대상 파일을 읽고 `convention.md`의 각 항목을 하나씩 대조한다.
   - 네이밍: 변수·함수 카멜 케이스, 컴포넌트 파스칼 케이스, 상수 UPPER_SNAKE_CASE
   - 포매팅: 들여쓰기 2칸, 한 함수 한 역할
   - 코드 품질: `console.log` 잔존 여부, 하드코딩된 URL·숫자, DB 코드의 try-catch, 오류 응답의 HTTP 상태 코드
5. 위반 사항을 보고한다.

## 보고 형식

1. 위반마다 `파일경로:줄번호`, 어긴 규칙, 수정 제안을 한 줄씩 적는다. 위반이 없으면 "통과"라고 알린다.
2. 모든 항목이 '통과'라면 '커밋 준비가 완료되었습니다!'를 출력한다.


## 주의

- 검사만 하고, 사용자가 요청하기 전에는 코드를 수정하지 않는다.
- 규칙에 없는 개인 취향의 스타일 지적은 하지 않는다.
- 판단이 애매한 항목(예: 함수가 한 역할인지)은 단정하지 말고 "확인 필요"로 표시한다.
